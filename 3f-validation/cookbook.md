# The Coded Action App — what bites

**Park a task at each gate before you write a line.** Aim one claim at each gate, leave both tasks waiting, capture your fixtures from those live records, and rebuild against them. An open gate's record differs from a closed one's — `decisionJson` holds the bare recommendation while claim review is open and `{recommendation, outcome}` after it (`contracts/claim-entity.md`) — and raising a gate again for every change costs minutes. Handle every shape your records show: `failedChecks` arrives as bare rule-id strings on some claims and as `{ruleId, name}` objects on others, from the same Agent.

**Build a local Action Center stand-in before the screens.** Serve the app in an iframe with `?basedomain=<the stand-in's origin>`: `@uipath/coded-action-app` posts only to that origin and accepts messages only from it. The app sends `AC.init` and the host answers `AC.loadApp` with the task. After that come `AC.dataChanged`, `AC.complete` (answer it with `AC.completeResponse`), `AC.displayMessage` and `AC.error`. Read the `AC.complete` payload off the wire, the one artefact the case consumes. Enforce two rules there: **spread the current payload first, then write the contract's names**, so the three `inOut` identifiers survive; and **omit an empty output rather than sending `""`**, because `""` clears the column on the way to the record. Look at all four states yourself before the reviewer does.

**Keep the outcome buttons enabled.** The skill's template disables them until the reason is written (`disabled={!isFormValid}`). Playwright then cannot click them, a screen reader never hears why, and the layout's reachability rule fails. When a press is not ready, move focus to the reason field and announce the requirement (`role="alert" aria-live="assertive"`).

| Issue | Fix |
|---|---|
| The whole app goes blank on Safari when a PDF opens | Use the skill's PDF viewer, and put it **inside its own error boundary**: pdf.js iterates a `ReadableStream` asynchronously, WebKit refuses, and an unguarded viewer blanks the whole app. |
| Every document fails to open in the deployed app, though it opened in dev | The production build emits the pdf.js worker under a hashed name and the bundle asks for `assets/pdf.worker.mjs`. Import the widget's worker with `?url` (`@uipath/ui-widgets-pdf-viewer/pdf.worker.min.mjs?url`) and assign it to `pdfjs.GlobalWorkerOptions.workerSrc` at startup, then open one document in the deployed app. In dev, a blank page with *does not provide an export named default* from `lodash` needs `'@uipath/ui-widgets-pdf-viewer > @uipath/apollo-wind'` in `optimizeDeps.include` beside `react-pdf`, and `vite --force`. |
| The page renders blank; the console says *Invalid SDK instance. Make sure to pass a valid UiPath instance to the service constructor* | `new UiPath()` with no arguments is silently **unregistered** unless the host's meta tags supply a complete config (base URL, org, tenant, client id, redirect URI, scope). The template builds services at module scope, so the throw happens at import, before any error boundary. Build the session and the services lazily, on first use. Import each service class from its subpath (`@uipath/uipath-typescript/entities`, `/buckets`) and pass it the session. |
| The document panel says *Failed to fetch* while the claim record renders fine | **The SDK is pointed at the portal host.** `cloud.uipath.com` answers CORS for Data Fabric but not for Orchestrator, so the record loads and the bucket call dies (`uipath-coded-apps` rule 8). The platform sets `uipath:base-url` to `https://api.uipath.com` only when the packed `uipath.json` carries the client id, and `deploy` reads it from there, not from `--client-id`. Read the deployed page's `<meta name="uipath:*">` at the URL `deploy` registered on the shared client (`uip admin external-apps get <client id>`), not the URL it printed. Never ship `clientId: ""` (`CONFIG.md`). If you keep a fallback config, it uses `https://api.uipath.com` and *says on screen* that it is active. The working read is `buckets.getByName(name, folderScope)`, then `getReadUri(bucketId, path, folderScope)`, then `fetch` on the pre-signed URL → blob → object URL. Classify a caught error before wording it (*unreachable* / *refused* / *other*), and put the file and bucket name on the card. |
| A document the record names is *not found* in its bucket | Blob paths are stored with a **leading slash**: `uip or bucket-files list` reports `/HO-27088985.pdf` while the record's `*PdfName` column holds `HO-27088985.pdf`. Ask for `/name`, then `name`. `bucket-files` takes the bucket's GUID `Key`, not the numeric `Id` that `uip or buckets list` also prints. |
| `uip tasks list` shows every task with `Data: null` | The list never carries payloads. Only `uip tasks get <id>` returns `Data.{recordId, claimId, triggerStage}`. `tasks assign` takes **no** `--folder-key`, while `list`, `get` and `complete` all do. |
| The skill interviews you for a new app: name, schema, scopes, client id, layout | Skip its pre-flight. `CONFIG.md`, `contracts/review-task.md`, `layout.md` and `brand.md` answer every question, and the app already exists. Edit the app you have. |
| `app.config.json` no longer carries `deploymentId` after a republish | `publish` rewrites the file without it. Take the action-app id the case binds from `uip maestro case registry pull -f`, and the app's version from the deploy's output. |
| Tasks raised earlier stop matching your app, or `uip codedapp deploy` upgraded once and now answers `400 invalid app version in request body` on every version | **Two published app models carry one title.** Either the app was published in two folder contexts, or the solution provisioned a copy: an `app` entry under `resources/solution_folder/` (`CONFIG.md`, *Deploying*), which deploys as a shell with `Definition.Id` null, so the gates fault with `170000 Failure in the AppTasks request`. Existing tasks stay pinned to one model while deploys upgrade the other. Neither carries `latestInFeed`, so the CLI PATCHes your deployment with the highest version it finds. The live app is unaffected. Deploy only with `--folder-key <seat folder>` (`publish` takes no folder). To remove a solution copy, delete the solution's `app` resource, repack, and redeploy the solution once. A copy already on the tenant leaves the upgrade to a hand-made PATCH with the right integer. |
| `codedapp pack` refuses `-a` / `-o`, or `publish` finds nothing | `pack` takes `--author` and `--output-dir` — the skill's examples still show `-a` / `-o`, and `--output` is the output *format*. A failed `pack` leaves `publish` nothing to find. |
| The URL `codedapp deploy` printed answers 404 | The app is served at the routing name of its first registration: read `<meta name="uipath:app-base">` from the served page. An Action app prints no URL at all. |

## What only Action Center shows

| Issue | Fix |
|---|---|
| An untouched task shows "this claim has been decided" | An *unassigned* task arrives `isReadOnly: true`. A task is decided when `status` is Completed or `action` is set; read-only is a separate state. The local stand-in cannot show this. |
