# The Process App — what bites

| Issue | Fix |
|---|---|
| The deployed app's sign-in bounces to `localhost:5173` | The skill's template applies the dev Vite plugin (`@uipath/coded-apps-dev`) to the production build as well, so `dist/index.html` carries its own `<meta name="uipath:*">` tags; the platform appends its tags after them and the first `redirect-uri` wins. Apply the plugin to `serve` only — `{ ...uipathCodedApps(), apply: 'serve' }` — and fail the build if `localhost` appears anywhere in `dist/`. |
| Two copies of React — *Invalid hook call* — after sharing the claim view from the Action App by a Vite alias | A bare import inside the shared tree resolves against the **other** app's `node_modules`. Alias every package both trees import — `react`, `react-dom`, `react-pdf`, `pdfjs-dist` — to this app's copy; `resolve.dedupe` alone does not reach files outside the project root. Point `tsconfig` `paths` at the shared source without `baseUrl`, which TypeScript 6 refuses (`TS5101`). |
| The *Decide as* list is empty and every press says *choose who you are* | `Tasks.getUsers` returns every cloud sign-in as `DirectoryUser`, not `User` — keep both, never robots or groups. The SDK has no call for the signed-in user, so the handler picks themselves; the app assigns the task to them, then completes it: Action Center accepts a decision only from the assignee. |
| A press that did not send looks like one that did | Show why a decision was not sent beside the buttons, where *sent* appears — never in a separate box. |
| The stage strip shows an *Undefined* stage, or several current ones | `CaseInstances.getStages` returns an unnamed entry and keeps finished stages *in progress* after the claim closes. Let the record's `status` decide the current stage, take each stage's time and deadline from the case, and hide stages the claim never reached. |
| A pending task has no `recordId` / `claimId` / `triggerStage` | `Tasks.getAll` rows carry no `data`. Hydrate each pending task with `getById` before reading its identifiers, and join on that `claimId` — never on title, order or timing. |
| Every service fails at once with `invalid_scope` | One scope beyond the shared registration's list fails the whole token. `uipath.json`'s `scope` is exactly `CONFIG.md`'s list; a scope the registration lacks is the operator's to add. |
| A label reads like a debug dump, or a failed call shows sample data | The dashboard and the claims list follow the claim screen's rules (`3f-validation/layout.md`, *Rules that are not optional*): prose labels, never a status word or payload key; an error state that names the call, no mock data; fixtures only behind `import.meta.env.DEV`, never shipped. |

`uip codedapp pack`, `publish` and `deploy` behave here as in block 3f — without `-t Action` — and their traps are the `codedapp` rows of `3f-validation/cookbook.md`.
