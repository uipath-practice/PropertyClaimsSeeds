# The Process App — what bites

**Reconcile numbers against the record, not against the screen.** `uip df records list` is the truth the dashboard summarises; a count that disagrees with it is a bug in the app, whatever the chart says.

| Issue | Fix |
|---|---|
| The deployed app's sign-in bounces to `localhost:5173` | The dev Vite plugin (`@uipath/coded-apps-dev`) injects the `<meta name="uipath:*">` tags into the **production** build too, and the platform appends its own around the built head — two `redirect-uri` tags, and the first wins. Apply the plugin to `serve` only (`{ ...uipathCodedApps(), apply: 'serve' }`) and fail the build if `localhost` appears anywhere in `dist/`. |
| You cannot sign in locally at all | The local sign-in needs a human's browser; an automation browser has no tenant session. Prove the numbers without one: bundle the app's own aggregation module and run it over the rows the CLI read, and compare with an independent count. The signed-in checks — the dashboard opens, a search, a decision completed from the app — are the operator's, on the deployed URL. |
| Two copies of React — *Invalid hook call* — after sharing the claim view from the Action App by a Vite alias | A bare import inside the shared tree resolves against the **other** app's `node_modules`. Alias `react` and `react-dom` to this app's copy (or `resolve.dedupe`), and point `tsconfig` `paths` at the shared source without `baseUrl` — TypeScript 6 refuses it. |
| The whole app goes blank when a document opens, on Safari or any WebKit view | pdf.js iterates a `ReadableStream` asynchronously, which WebKit refuses, and the throw escapes the viewer. Keep the document viewer inside its **own** error boundary so a viewer failure costs one panel, not the page. |
| The straight-through share counts claims no human ever saw as reviewed | `eligibilityDecision` and `reviewDecision` are filled by the case's convergence write on every claim, human or not. Read **who decided** from the gate conditions themselves — whether the screening checks all passed, and `reviewRequired` — not from the decision words; the count of gates opened must equal the tasks ever raised. |
| Sign-in bounces straight back, or every service fails at once with `invalid_scope` | `uipath.json` asked for a scope the shared registration does not grant, and one refused scope fails the **whole** token. Its `scope` is exactly the registration's list (`CONFIG.md`) — no more. Adding a service means the scope has to exist on the registration first; that is the operator's, not yours. |
| Local sign-in fails with a redirect mismatch | `http://localhost:5173` has to be on the shared registration's redirect list; the deployed URL is registered for you by `deploy`. Neither is fixed with `external-apps update` — it replaces the list for everyone. Tell the operator. |
| `task.complete` answers `401` / `403`, naming neither service nor scope | Completing a task is a write; it needs `OR.Tasks` on the registration and in `uipath.json`. Read the scopes, do not retry. |
| The claims table shows a handful of rows and calls it everything | **Every list call returns one page**, with no option to ask for all. Loop the cursor until `hasNextPage` is false, then paginate the table 25–50 rows with a count. |
| A task row has no `recordId` / `claimId` / `triggerStage` | `getAll` rows omit `data`. Hydrate each pending task with `getById` before reading its identifiers, and join tasks to claims on `claimId` from that payload — never on title, order or timing. |
| The wrong task gets completed, or none is found | Filter pending server-side (`Status ne 'Completed'`) in the seat folder and match on the hydrated `claimId`. If no task matches, say so and stop; never widen the search to "any pending task". |
| Completing from the app leaves the task with an empty payload | Every writer **replaces** the task payload. Send the outcome as the task's action string, the outputs, **and** the three inOut identifiers back (`contracts/review-task.md`, *What survives completion*). |
| `TaskCompleteOptions` will not type-check with a conditional spread | It is a discriminated union on `type`; branch explicitly per task type. A Maestro gateway task bound to a coded action app is an app task, and its outcome string must be one the case routes on (`Proceed` · `Refuse` · `Approve` · `Deny`). |
| You want a link to the task in Action Center | `https://cloud.uipath.com/<org>/<tenant>/actions_/current-task/tasks/<taskId>` — from the task's id, never guessed. |
| The record loads but every bucket or task call dies with *Failed to fetch* | The SDK is pointed at the portal host. `baseUrl` is `https://api.uipath.com`; `vite.config.ts` sets `base: './'`; runtime absolute URLs go through `getAppBase()`. |
| A service import fails or a method does not exist | Import services from their subpath and construct them with the SDK (`new Entities(sdk)`), never from the package root and never by dot-chain. Signatures come from `node_modules/@uipath/uipath-typescript/dist/<service>/index.d.ts`, not from memory. |
| Columns are missing from a row | A column never written is **absent**, not `null` — most columns of an in-flight claim. Read every column defensively and treat absent and empty alike (`3b-entity/cookbook.md`). |
| The decision column parses to two different shapes | `decisionJson` holds the recommendation envelope while the review gate is open and recommendation plus outcome after it closes. Read both; key on the record's `reviewRequired` and `reviewDecision`, never on which keys happen to be present. |
| The stage strip shows stages your case does not have | Stages come from the case — your `sdd.md` Section 2 and the record's `status` vocabulary, or `CaseInstances.getStages()` on the instance — never from a list typed into the app. |
| A total across the portfolio looks wrong | Six currencies, no conversion (`PDD.md` A2). Count claims freely; sum amounts per currency only. |
| The case analytics calls fail while the record reads fine | The Insights and Maestro analytics methods need scopes the shared registration may not carry. Everything the dashboard needs can be computed from the record; use the case API only for what the record cannot know. |
| A PDF will not display; the document panel says *not found* | Same as the Action App: the host blocks native embedding, so render with a JavaScript viewer; read the file from its bucket by `getReadUri`; bucket paths carry a leading slash the record's name column does not (`3f-validation/cookbook.md`). |
| Labels read like a debug dump | Never render a payload key, an enum token or a status word as a label. Every string a handler reads is prose — *Awaiting inspection*, not `stage-awaiting-inspection`. |
| The app looks finished while a call is failing | No sample or mock fallback on any error path. A failed call renders an error state that names the call. Fixtures load only behind an explicit development flag and never ship. |
| `codedapp deploy` printed a URL that 404s | Activation lags the deploy by minutes; do not poll it. The slug is whatever the app was registered under the first time — read it from the served page's `<meta name="uipath:app-base">` if it ever differs from the name. |
| `codedapp deploy` fails `400 Failed to update external client redirect URI` | The shared redirect list is full. Nothing about your app is wrong; tell the operator (`CONFIG.md`). |
