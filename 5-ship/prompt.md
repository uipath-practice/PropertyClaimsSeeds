# Ship

Everything runs. This block makes it something somebody else could take.

You deployed pieces as you built them, to test them. **That is not the same as shipping a solution** — a package that only works because of what is already sitting on your seat is a package that works nowhere else.

Use the **`uipath-solution`** skill. Pack the whole thing, publish it, deploy it under the one name `CONFIG.md` pins, and then **prove it from the package**: a claim run end to end on what you just deployed, not on what was already there.

Check what travelled. A coded app is not part of the solution and does not go with it unless you put it there — `3f-validation/cookbook.md`. Anything you deployed by hand while building is a candidate for having been left behind.

Then write down what an operator would need and does not have: how it is deployed, what has to exist first, what is known-broken, and what to do when a claim faults. That last one you already know better than anyone, because you have been doing it all week — **and most of it is already in `PROGRESS.md`**, which has been accumulating exactly these facts since block 1. This is a rewrite for a different reader, not a fresh investigation: the runbook is for a human operating the solution, the handover was for the agent building it.

**Done when** the solution deploys from its package into a folder that did not previously contain it, and a claim runs through to a decision letter.
